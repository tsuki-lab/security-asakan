セキュリティ朝刊

10月25日（日）の朝刊

今日のひとこと：スマホ・PC・ブラウザを「最新に更新して再起動」。大きな新事件はなく、先日の話の続報が中心です。

1偽サイト用の「鍵」流出の続報：Apple も対策を広げました

iPhone・Mac のブラウザ側の対策はさらに進みました。27日にはもう一段、Chrome が対応します。

先日お伝えした、インドの会社 eMudhra の鍵の流出について、Apple が10月23日に対策を広げました。Safari など Apple の標準の仕組みを使うアプリは、自動の更新で守られます。Chrome は10月27日（日本時間では28日未明）に、この会社の古い「身元保証」の登録そのものを外す予定です。その日から、この会社の証明書を使ったままのサイトでは警告画面が出ることがあります。

この会社は、Web サイト向けの証明書の事業から撤退する方針です。今のところ、鍵が悪用されたという報告はありません。

みんながやること
  • スマホ・PC・ブラウザを最新にして、一度再起動する
  • 警告画面が出たサイトには、先へ進まずに閉じる。普段使うサイトなら、運営からのお知らせを待つ

2PHP に、修正版のない新しい欠陥が見つかりました

ごく限られた設定のサイトだけが対象で、設定を一つ変えれば防げます。

先日修正された欠陥とは別に、10月23日に新しい欠陥が公表されました。まだ修正版はありませんが、特殊な使い方をしているサイトだけが対象で、悪用の報告もありません。サイトの運営側が設定を一つ変えることで防げます。

みんながやること
  • 利用者としては特にありません。使っているサービスのお知らせに目を通す程度で大丈夫です
  • 自分でブログやお店のサイトを持っている人は、サーバー会社の案内を確認する

3会社や学校のネットワーク機器への攻撃が続いています

個人のスマホやパソコンに直接の影響はありませんが、勤め先の機器が狙われています。

米国の政府機関（CISA）が、遠隔会議や文書編集に使う Collabora Online と、拠点をつなぐ Arista VeloCloud の欠陥が実際に悪用されていると警告しました。Cisco のメール用の機器や Ivanti の VPN 機器でも、悪用が続いています。ランサムウェア（データを人質にして身代金を求める攻撃）集団が、Palo Alto の機器の欠陥を狙う動きも報告されています。

みんながやること
  • 勤め先で社内のネットワーク機器を担当している人は、メーカーの案内に沿って更新する
  • それ以外の人は、会社からの「更新してください」という連絡に従って、早めに再起動や更新を済ませる

いつでも効く3つの基本

  1. OS・アプリ・ブラウザは自動更新をオンにして、ときどき再起動する
  2. パスワードはサービスごとに変え、二段階認証（ログイン時の確認コード）をオンにする
  3. 急がせるメール・SMS・DM のリンクは開かず、公式の入り口から確かめる

エンジニア向け

ここから先は、サービスの開発や運用をしている人向けの情報です。前号で既出の話は続報だけ載せています。

1. eMudhra：Apple がルートも遮断。ターミナルのツールは別

  • Apple（サポート記事 149555、10/23）：10/19 の中間証明書に続き、emSign ECC Root CA – G3 自体も遮断。自動の設定更新で届く。
  • macOS 標準の curl・git・python3・ruby・perl・openssl が読む /etc/ssl/cert.pem には効かない。Apple は「将来のソフトウェア更新で直す」とし、急ぐ管理者向けにこのルートを外す手順を公開（macOS の更新でファイルが戻ることがある）。
  • Chrome：G3 を 10/27 朝（米国太平洋時間）に外す見込み。G3 の下の証明書を使っているサイトは、全画面の警告が出うる。emSign Root CA – G1 の扱いも Chrome が見直していると報じられている（Mozilla は G1 を残している）。
  • eMudhra は TLS 証明書事業から撤退する方針で、影響を受ける顧客の証明書を同社が取り替えるとしている（協力先・時期は未公表）。原因は 2025年4月の鍵の生成作業の不備と説明。
  • 修正版（Node 22.23.4 / 24.22.1 / 26.12.1、certifi 2026.10.18、Go 1.27.3 / 1.26.10 など）は前号のまま。

2. PHP：CVE-2026-115560（修正版なし）

  • アプリが session.serialize_handler を php_binary か php_serialize にし、実行時に ini_set() で php に戻してから session_start() し、かつセッションのアップロード進捗が有効なときだけ、リモートでコードを実行されうる。
  • 回避策：session.upload_progress.enabled=0。PHP は次の定例リリースで直す予定で、悪用の報告はまだない。
  • PHP2Shell（CVE-2026-109618 / 109619）は修正版 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 のまま。探りの通信は確認されているが、侵害の確認はない。

3. 悪用が確認されているもの

  • CISA の悪用済みリストに Collabora Online と Arista VeloCloud（対応期限 10/26）。
  • Cisco Secure Email Gateway（CVE-2026-76519）：File Reputation が有効で、Content Scanner Tools が 25.3.0.5525 未満の機器が対象。
  • Ivanti Connect Secure（CVE-2026-104935）：認証回避のゼロデイ。連鎖する権限昇格の1件は未修正。
  • Palo Alto PAN-OS（CVE-2026-0257）：Qilin などが悪用を試行。修正は5月から提供。

4. LiteLLM 1.107.0 の続報

  • 入り口は、社内の検証環境のログから漏れた GitHub CLI の OAuth トークンと報じられている。公開されているのは 10/21 の約2時間（PyPI）。安全な版は 1.106.2。入れた環境は作り直し、そこから届く鍵とトークンをすべて交換する。
