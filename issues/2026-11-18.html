セキュリティ朝刊

11月18日（水）の朝刊

今日のひとこと：楽天証券やよく使うお店を名乗る「確認してください」というメール・SMS・電話が来ても、リンクは開かず、公式アプリや公式サイトから自分で確かめてください。

1楽天証券から最大約447万口座分の個人情報が漏れたおそれ。年収や出金先の口座も

楽天証券は11月17日、不正アクセスで、お客さんの情報が外に漏れたおそれがあると発表しました。

最大約447万口座（解約した人を含む）は、氏名・住所・生年月日・電話番号・メールアドレス・勤務先・出金先の銀行口座・申告した年収や資産などが対象です。ほかに最大約1,125万口座のログイン ID も含まれます。パスワードと暗証番号の漏えい、不正な取引は確認されていないとしています。

みんながやること
  • 楽天証券を使っている人は、ログイン時の「パスキー」を設定する。ログイン後のセキュリティ設定で、取引や出金を一時的に止めることもできる
  • 年収や資産を知った上での「投資のお誘い」「本人確認のお願い」は詐欺を疑い、楽天証券を名乗る連絡のリンクは開かない

2お店やサービスの「お客さん分析」の仕組みから流出。JINS・Francfranc などが次々に公表

前号で伝えた KARTE（多くの会社がサイトの裏側で使う分析サービス）への不正アクセスで、利用していた会社が自社のお客さんの情報も流出したおそれがあると発表し始めました。

JINS は最大約1,829万アカウント（メールアドレス・生年月日など）、Francfranc は最大約598万件（氏名・生年月日など）、クラブツーリズム約406万件、アインズ＆トルペ・アユーラ最大約260万件など、30社近くが公表しています。日経電子版・WOWOW・集英社・CAMPFIRE・mineo なども調査中です。多くの会社は、パスワードやカード情報は対象外としています。

みんながやること
  • 使っているお店やサービスから届いたお知らせは、メールのリンクではなく公式サイトで内容を確かめる
  • 流出をきっかけにした「ポイント付与」「確認のため入力を」というメール・SMS は開かない

3BBC・CNN・Zoom などの大手サイトに、カード情報を盗むコードが一時的に仕込まれた

多くの会社がサイトの見た目を試すのに使う外部サービスが乗っ取られ、11月16日に少なくとも178の組織のサイトで不正なコードが配られました。

コードは、サイトの入力欄に打ち込んだカード番号を盗んだり、暗号資産の送金先を差し替えたり、古い iPhone を狙ったりするものでした。サービス側はすでに直し、コードは取り除かれています。

みんながやること
  • iPhone・iPad を最新の iOS に更新する
  • 11月16日に海外の大手サイトでカード払いをした人は、カードの明細に覚えのない請求がないか確かめる

いつでも効く3つの基本

  1. OS・アプリ・ブラウザは自動更新をオンにして、ときどき再起動する
  2. パスワードはサービスごとに変え、二段階認証（ログイン時の確認コード）やパスキーをオンにする
  3. 急がせるメール・SMS・DM のリンクは開かず、公式の入り口から確かめる

エンジニア向け

ここから先は、サービスの開発や運用をしている人向けの情報です。前号で既出の話は続報だけ載せています。

1. Optimizely Web Experimentation の改ざん（11/16）

  • Optimizely の欠陥を突いて各社の Project JavaScript にローダーを書き込み、正規の cdn.optimizely.com から配信。少なくとも 178 組織（CNN・BBC・Zoom・Salesforce・GitLab・HSBC など）。最初の注入は 11/16 04:21 UTC、大半は同日 21:52 UTC までに除去。再感染した例もある。
  • 中身：暗号資産アドレスのすり替え（1688360[.]cc/track.js）、自前フォームのカード番号・期限・CVV の窃取（別オリジンの決済 iframe は読めない）、HttpOnly でない Cookie と画面の送信、iOS 13〜18・26 向けの攻撃チェーンのローダー。
  • やること：Project JavaScript とカスタムコードで 1688360・atob(・覚えのないコードを探す。Optimizely に書き込めるアカウント・API トークンを交換。CSP の script-src / connect-src を絞る（cdn.optimizely.com を許可するだけでは防げない）。決済ページに第三者タグを置かず、決済代行の別オリジンの入力欄を使う。11/16 に自社フォームに入ったカード情報は漏れた前提で扱う。

2. Oracle Java の 11 月の更新（11/17）と「Java4Shell」CVE-2026-114938

  • Oracle は Java SE の 11 件を修正。修正版は 8u513・11.0.33.1・17.0.21.1・21.0.13.1・25.0.5.1・27.0.1.1。GraalVM・JavaFX も対象に挙がっている。
  • Java4Shell は Calif の報告で、OpenJDK 17.0.6 以降・CVSS 4.0 で 9.2 と報じられたが、CVE は予約のみで Oracle の 11 件に含まれるかは不明。AVX-512 の Base64 デコードの欠陥で JVM が落ちる程度との分析もある。悪用の報告はまだない。
  • やること：Oracle JDK は上の版へ。Temurin・Corretto・Zulu・ディストリの OpenJDK は各配布元の 11 月の版が出たら当てる。外から受け付けるサービスを優先し、Docker イメージは作り直す。

3. KARTE（プレイド）の続報

  • プレイドは 11/17 20:53 の更新で、漏えいを確認したデータ（「紐付けテーブル」などで取り込んだもの）を申請のあった利用企業へ送り始めた。再開は未定。
  • 利用企業の公表：JINS 最大約1,829万アカウント、Francfranc 会員 最大約598万件＋購入履歴 最大約400万件、クラブツーリズム 約406万件、アインズ＆トルペ・アユーラ 最大約260万件、四国電力 約60万件、阪急阪神ホテルズ 最大331,586件 ほか。件数は集計単位が違い合算できない。
  • やること：KARTE の外部連携用のシークレットキー・アクセストークンを無効化し、連携先のログを確認。取り込んだ顧客データの項目を洗い出し、個人情報保護委員会への報告・本人通知の要否を判断。

4. 楽天証券：テスト環境から本番相当の顧客データ

  • テスト環境のシステムに置いていた情報が 11/11 に漏えいしたおそれ（11/16 検知）。最大約447万口座の氏名・住所・勤務先・出金先口座・年収・資産など、最大約1,125万口座のログイン ID。
  • 教訓：テスト・検証環境に本番の個人データを置かない（置くならマスキング・合成データに）。テスト環境も本番と同じ監視・アクセス制御の対象にする。

5. CISA KEV・その他

  • Perforce Puppet Enterprise CVE-2026-115731（信頼できないデータのデシリアライズ）を 11/17 に KEV へ追加。修正版は 2023.8.13 / 2025.12.1 / 2026.0.1 以上と各所が案内している（Perforce の原文は未確認）。更新まで証明書要求の自動署名を止める。
  • 富岳：利用者 4,222人の氏名・メール・ユーザー ID と SSH 秘密鍵・アクセスキーが流出。盗まれたキーでほかのシステムへの接続も試みられた。共有の計算機・踏み台に置いた鍵は交換を。
