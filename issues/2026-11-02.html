セキュリティ朝刊

11月2日（月）の朝刊

今日のひとこと：「情報が漏れた」と知らせるメールや、買い物の最後に出る見慣れない画面にはご用心。リンクは開かず公式サイトから確かめ、カード番号は正規の画面だけで入力してください。

1メール配信サービスから、延べ約5,163万件のメールアドレスなどが流出

企業がメルマガなどを一斉に送るために使う「Cuenote（キューノート）」で、配信先の情報が大量に外へ出ました。

運営するユミルリンクが10月27日に第二報を発表しました。10月16日に不正アクセスに気づき、延べ51,628,280件の情報が流出した可能性があります。メールアドレスのほか、氏名・都道府県・生年月日などが含まれることがあります。まだ調べているシステムがあり、件数は増える可能性があります。みなさんが直接契約しているサービスではなく、メルマガを送ってくる会社が使っていた、という形での被害です。

みんながやること
  • メルマガや会員登録をした会社から連絡が来たら、内容を読み、リンクではなく公式サイトのお知らせで確かめる
  • 「あなたの情報が漏れました」「今すぐ確認を」といった便乗メール・SMS のリンクは開かない
  • 身に覚えのない宛先からのメールが増えたら、返信せず迷惑メールに振り分ける

2楽天トラベルの海外ホテル予約などで、最大約260万件の利用者情報

楽天トラベルの一部のページが不正アクセスを受け、予約者や会員の情報が漏れた可能性があります。

楽天グループが10月26日に発表しました。海外ホテル予約サイトの一部ページでは、予約者最大約4万件の氏名・メール・電話番号・予約内容が対象で、うち最大約3.6万件はカードの下4桁・名義・有効期限も含まれます。ログインしていた利用者の氏名・メール・電話番号は最大約260万件です。多言語の予約サイトでも最大約86万件のメールアドレスなどが対象です。対象の人には会社から個別に連絡が行きます。

みんながやること
  • 楽天トラベルを使った人は、会社からの連絡を確認する（連絡メールのリンクではなく、公式サイトのお知らせから）
  • カードの利用明細に身に覚えのない請求がないか見る
  • 予約を装った偽のメール・SMS・電話に注意する

3ネットショップの購入ボタンが、偽の支払い画面につながっていた

お店そのものではなく、お店が使っていた「お気に入り機能」の外部サービスが改ざんされ、買い物の最後に偽サイトへ飛ばされる被害がありました。

自転車ブランド「SHIPS CYCLE MARKET」を運営する Free Standard が10月22日に発表しました。10月14日の夜から15日の未明にかけて、購入手続きのボタンを押すと、本物そっくりの偽サイトに案内された可能性があります。お店のデータが盗まれたわけではありませんが、偽サイトにカード情報を入力した人がいるかもしれません。

みんながやること
  • この期間にこの店で買い物をした人は、カードの利用明細を確認する。身に覚えのない請求があればカード会社へ連絡する
  • 買い物では、カード番号を入れる前に、画面のアドレス（URL）がいつものお店のものか見る習慣を

いつでも効く3つの基本

  1. OS・アプリ・ブラウザは自動更新をオンにして、ときどき再起動する
  2. パスワードはサービスごとに変え、二段階認証（ログイン時の確認コード）をオンにする
  3. 急がせるメール・SMS・DM のリンクは開かず、公式の入り口から確かめる

エンジニア向け

ここから先は、サービスの開発や運用をしている人向けの情報です。前号で既出の話は続報だけ載せています。

1. ユミルリンク Cuenote：ライブラリの脆弱性から認証情報を取られ、49システムで流出（第二報 10/27）

  • Cuenote FC（一斉配信）：延べ 51,628,280 件。アドレス帳（メールアドレス・氏名・都道府県・生年月日など）、配信記録、Web アクセス記録（申込ページ・マイページ）、利用企業の担当者情報。Cuenote BASE：190 件（企業名・氏名・電話・メール）。調査中のシステムが 16 ある。
  • 経路：ライブラリの脆弱性を突かれ、サポート・品質管理担当者のサービス認証情報を取得 → 不正プログラムを設置 → DB からデータを出力。取得した認証情報で他システムへの認証も試行され、45 システムでは他システムのデータの参照とログイン時のセッション情報を使った不正ログインも確認。
  • やること：メール配信・顧客管理の SaaS を使っている／運用している場合は、ベンダーからの通知を確認し、連携用の API キー・管理画面のパスワード・セッションを見直す。サポート用・運用用アカウントの権限の棚卸しと多要素認証。（ScanNetSecurity の記事を読んだ。会社の原文は未読）

2. PingCAP（TiDB Cloud）：流用された認証情報で社内システムに侵入、国内最大約 5 万件

  • 米国時間 9/9〜10/7 に不正取得されたアカウントの認証情報で社内システムにアクセスされ、データの複製を取られた。10/7 に認識し、影響を受けた認証情報の無効化を開始。
  • 流出：TiDB Cloud のアカウント情報（ユーザー名・メール・組織／プロジェクトの関連付け・SQL エディタの実行履歴とエラー情報・サポートチケット）、取引関連情報（氏名・メール・企業名・電話・注文内容・支払い条件・請求設定）、API キーの Public Key 部分。
  • やること：TiDB Cloud を使っていれば、API キーの再発行、SQL 履歴・サポートチケットに貼った接続情報やクエリ内の秘密情報の洗い出し、不審なアクセスの確認。（ScanNetSecurity の記事を読んだ）

3. 外部アプリ経由のスキミング：Swym Wishlist Plus（Shopify 系の外部アプリ）

  • 開発元 Swym のシステムが侵害され、日本時間 10/14 19:06〜10/15 1:32 ごろ、購入手続きボタンを押すと偽の決済画面へ誘導するスクリプトが読み込まれた可能性。店舗 DB の情報の流出はないとされる。開発元は予防措置で全ショップで機能を一時停止。（ScanNetSecurity の記事を読んだ）
  • やること：サードパーティの JS を決済画面で読み込んでいないか確認する。読み込むなら CSP（Content Security Policy）と SRI、読み込み元の最小化、改ざん検知を。

4. 楽天トラベル（10/26 発表）

  • 海外ホテル予約ページ（子会社管理の一部）：9/10 に異常を検知、9/15 に原因特定、9/16 に改修。多言語予約サイト：10/20 に検知、10/21 に改修。宿泊施設従業員のアカウント最大約 4 万件（アカウント名・メール）も対象。侵入経路は記事に記載なし。（ScanNetSecurity の記事を読んだ）

5. 続報：eMudhra・Rust の webpki-roots・PHP2Shell・Brotli・LiteLLM

  • eMudhra：Chrome の emSign ECC Root CA – G3 の削除（10/27 PT の予定）が実施されたことは直接は確認できず、Apple の /etc/ssl/cert.pem を直す macOS 更新も見つからなかった。発行元に emSign / eMudhra があれば別の CA で取り直す。eMudhra は TLS 証明書事業から撤退を表明している。
  • Rust：webpki-roots は 1.0.10 以上（できれば 1.0.11）、rustls-webpki は 0.103.16 以上へ。cargo audit で RUSTSEC-2026-0381 / 0382 / 0383 を確認。
  • PHP2Shell（CVE-2026-109618 / 109619、悪用あり）：修正版は 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35。8.1 以前は公式の修正なし。CVE-2026-115560 の回避策は session.upload_progress.enabled=0。
  • Brotli の C 実装（CVE-2026-111497）：1.2.1 / 1.1.1 / 1.0.10。Node.js は 22.23.4 / 24.22.1 / 26.12.1。LiteLLM 1.107.0 はマルウェア版（安全な版は 1.106.2）。
  • CISA KEV の11月分の追加、npm / PyPI の新しい侵害は、今朝の検索では確認できなかった（確認できなかっただけで、無いとは限らない）。
