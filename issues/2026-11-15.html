セキュリティ朝刊

11月15日（日）の朝刊

今日のひとこと：同じパスワードを複数のサービスで使っているなら、今日それぞれ別のものに変えてください。無印良品の件は、よそで漏れたパスワードの使い回しを狙われたとみられています。

1無印良品の不正ログイン、原因は「パスワードの使い回し」を狙う攻撃か

良品計画は、MUJI アプリやネットストアへの不正ログインについて、ほかのサービスで漏れた ID とパスワードを使った攻撃の可能性が高いと判断しました。

対象は最大約2,726万件で、一部は氏名・住所・電話や、MUJI Card のカード番号も含みます。ネットストアは止まったままで、再開するときは全員にパスワードの再設定を求める方向です。対象者には11月10日からメールや郵便で連絡が始まっています。

みんながやること
  • 同じパスワードを使い回しているサービスがあれば、それぞれ別のパスワードに変える（パスワード管理アプリを使うと楽）
  • MUJI Card を持っている人は利用明細を確認する。無印良品やカード会社を名乗るメール・電話には注意する

リスト型攻撃：どこかで漏れた ID とパスワードの組を、別のサービスで片っ端から試す攻撃。使い回していると次々に入られます。

2「警察庁推奨アプリ」を勧める SMS は偽物

警察庁を名乗る SMS から偽サイトに誘い、詐欺対策アプリを装った危ないアプリを Android に入れさせる手口が出ています。

警察庁が11月11日に注意を呼びかけました。偽アプリは本物の詐欺対策アプリの名前をかたり、入れると「デバイスのフルコントロール」などの許可を求めます。調べられた偽アプリには、入力した文字や画面を盗み見る仕組みがありました。警察が SMS でアプリを案内することはありません。

みんながやること
  • アプリを勧める SMS のリンクは開かない。アプリは Google Play・App Store から自分で探して入れる
  • アプリが「フルコントロール」「ユーザー補助」などの強い許可を求めてきたら、許可しない

3Chrome の更新、まだの人は今日のうちに

11月9日に出た Chrome の更新は、すでに攻撃に使われている欠陥を直すものです。

Chrome は自動で更新されますが、ブラウザを閉じるまで新しい版に切り替わりません。iPhone・iPad・Mac、Windows にも今月の更新が出ています。

みんながやること
  • パソコンは右上のメニュー →「ヘルプ」→「Google Chrome について」を開いて更新し、「再起動」を押す。Android は Play ストアで Chrome を更新
  • スマホとパソコンの「ソフトウェアアップデート」「Windows Update」も確かめる

いつでも効く3つの基本

  1. OS・アプリ・ブラウザは自動更新をオンにして、ときどき再起動する
  2. パスワードはサービスごとに変え、二段階認証（ログイン時の確認コード）をオンにする
  3. 急がせるメール・SMS・DM のリンクは開かず、公式の入り口から確かめる

1. 「wfx」：乗っ取った GitHub アカウント 4,837 個で CI のシークレットを窃取（11/10〜）

  • 11/10 12:45 UTC ごろから、ブランチ wfx-docs の PR「docs: dependency audit notes」を 61,764 リポジトリに出して書き込み権限を確かめ、その後ワークフローへの追加（コミット「ci: refresh build cache」）や package.json の postinstall（.ci-xxxxxx.sh、コミット「chore: add ci helper」）、.github/workflows/build-audit-xxxxxx.yml（「chore: add dependency audit workflow」）を入れた。SafeDep の集計で公開リポジトリ 8,093 件、少なくとも 1,806 件で実行。直後に「ci: restore」「ci: cleanup」で revert する。
  • 盗むもの：Actions のシークレット・変数・GITHUB_TOKEN・OIDC トークン、クラウド / Kubernetes / npm / PyPI / SSH の認証情報、AI サービスのキー、リポジトリ全体。AWS では IAM ロールの信頼ポリシーの書き換えや長期キーの作成、Azure では wfx-ci-* のフェデレーテッド資格情報の追加で裏口を残す。
  • 汚染されたパッケージ：Packagist digitalelvis/neuronai-studio 3.14.3（3.14.2 以前に固定）、Go github.com/onuragtas/docker-env v1.0.278 / v1.0.280、github.com/vkuznet/gocurl の擬似版 v0.0.0-20261111095532-8d5aad0cb0da。npm・PyPI の悪性版の名前はまだ報告されていないが、公開者アカウントも含まれるので新しい版の install hook に注意。
  • やること：git log --all --since=2026-11-10 で上のコミットメッセージを探す、git ls-remote origin 'refs/heads/wfx-docs' 'refs/heads/chore/*' 'refs/heads/ci-check-*'、ワークフローの toJSON(secrets) と run 番号の欠番を確認。見つかれば CI から届いたシークレットをすべて交換し、CloudTrail（CreateAccessKey・UpdateAssumeRolePolicy）・Entra・GCP・Vault の監査ログで裏口を消す。通信先 194.150.166[.]244:8080・18.143.168[.]96:8080・153.75.82[.]159:8080 を遮断。

2. Git 2.56.1 ほか：再帰クローンでコード実行（CVE-2026-111760）など 6 件（11/10）

  • CVE-2026-111760：インデックスのパス長の整数切り捨てで、細工したリポジトリを --recursive でクローンするとサブモジュールの .git が置き換えられ、設定やフックでコード実行。CVE-2026-105437：大きなマージでのヒープ破壊（git merge-tree を動かすホスティング側が狙われやすい。GitLab は 19.5.4 / 19.4.6 / 19.3.8 で対応）。ほか CVE-2026-113408・CVE-2026-114467・CVE-2026-114469・CVE-2026-114466。
  • 修正版：2.56.1 / 2.55.1 / 2.54.1 / 2.53.1 / 2.52.1 / 2.51.3 / 2.50.2。2.50 より前は修正なし。GitHub.com は対応済み、Actions・Codespaces・GitHub Desktop は順次。
  • やること：手元・CI イメージ・セルフホストランナーの Git を更新。更新までは信頼できないリポジトリを再帰クローンしない。

3. Next.js 16.4.5 / 15.5.29（11/3 のセキュリティリリース、7 件）

  • High：Cache Components で unstable_cache と use cache を組み合わせると、ルートパラメータ（テナント ID など）をまたいでキャッシュが漏れる（GHSA-mfr8-8qww-v76h）。
  • Medium：ネストした use cache（GHSA-vc7v-qv4w-wrv8）、バイナリ引数のキャッシュ衝突（GHSA-rhh4-g77r-r9qj）、自前運用の next start のシェルキャッシュ汚染、圧縮レスポンスのフレーミング不一致（GHSA-pc58-hwjq-p385）、Edge ルートで HttpOnly の cookie が x-middleware-set-cookie ヘッダに出る（GHSA-f3mh-rxg3-f5g2）、画像最適化の SVG 拒否の回避（GHSA-7qx7-33qx-rqx2）。
  • やること：next@16.4.5 か next@15.5.29 へ。本紙は 11/3 の発表をこれまで取り上げていませんでした。

4. eMudhra 続報：emSign Root CA - G1 の TLS distrust-after は 2026-11-16 23:59:59 UTC

  • Mozilla bug 2089115 のとおり、この日時より後に G1 の下で発行された TLS 証明書は、その NSS を使うクライアントで信頼されなくなる見込み（どの Firefox の版に入るかは未記載）。新しい動きは見つからなかった。
  • やること：自社のサイト・API の証明書チェーンに emSign / eMudhra があれば、別の CA で取り直す。

5. 漏えいの技術的な背景

  • 良品計画：11/7 にログイン状況の分析から「リスト型攻撃の可能性が高い」と判断。ネットストアは停止のまま、再開時に全員へパスワード再設定を求める方向。自社サービスでもレート制限・二段階認証・漏えい済みパスワードの拒否を。
  • サイバーセキュリティクラウド：従業員の GitHub の認証情報 1 件が外部に流出し、社内の GitHub 環境に不正アクセス（11/5 に履歴を確認、11/13 公表）。一部顧客の組織名・氏名・メールなどが流出した可能性。PAT・SSH 鍵は期限と権限を絞る。
