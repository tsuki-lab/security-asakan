セキュリティ朝刊

11月16日（月）の朝刊

今日のひとこと：宅配便や鉄道会社、お店を名乗るメール・SMS のリンクは開かず、公式アプリやいつものブックマークから確かめてください。住所や買った物まで知っている「本物らしい」連絡が増えそうです。

1京成スカイライナーのネット予約、会員情報 最大約337万件が流出の可能性

京成電鉄は11月13日、特急券のチケットレスサービスが不正アクセスを受け、会員情報が外に持ち出された可能性があると公表しました。

対象は会員の ID、暗号化されたパスワード、カナ氏名、電話番号、メールアドレスです。会社は「パスワードは暗号化されていて元に戻せない」と説明しています。ネット予約は止まっていて再開時期は未定ですが、駅の窓口と券売機では通常どおり買えます。

みんながやること
  • このサービスと同じパスワードをほかでも使っている人は、ほかのサービスのパスワードを変える
  • 京成電鉄を名乗るメールや電話が来ても、リンクは開かず公式サイトから確かめる

2通販の発送代行会社から届け先の情報が流出。「お届け」の偽連絡に注意

ネットショップの発送を請け負うオープンロジが不正アクセスを受け、荷物の届け先の情報が持ち出されました。

同社の11月11日の発表によると、対象は今年4月8日から11月8日までに発送を頼まれた荷物の、氏名・住所・電話番号・メールアドレス・商品名と数量です。クレジットカード番号は含まれません。件数は調査中です。グッズ通販など複数のショップが同社を使っていて、買った物の名前を添えた本物らしい偽の連絡が届くおそれがあります。

みんながやること
  • 「再配達」「お届け先の確認」をうたう SMS・メールのリンクは開かない。配送会社の公式アプリか、注文履歴の追跡番号で確かめる
  • 買ったお店から「お知らせ」が届いていないか、お店の公式サイトで確かめる

3AI に入力した内容が、裏側の会社から流出

メモアプリ Notion の AI 機能に入力した文章と AI の返事の一部が、Notion が AI の処理を任せていた会社への不正アクセスで流出した可能性があります。

対象は全体の1%未満の利用グループで、ふつうのページやファイルは対象外です。ただ、AI への質問文にパスワードや取引先の名前、他人の個人情報を書いていた場合は、それが外に出たおそれがあります。国内でも多くの会社が「社内の AI 利用で入力した内容が含まれる可能性」を公表しています。AI サービスは、目の前の会社とは別の会社の設備で動いていることがあります。

みんながやること
  • AI チャットにパスワード・暗証番号・カード番号・他人の個人情報を貼り付けない
  • 過去に貼ってしまったパスワードがあれば、そのパスワードを変える

いつでも効く3つの基本

  1. OS・アプリ・ブラウザは自動更新をオンにして、ときどき再起動する
  2. パスワードはサービスごとに変え、二段階認証（ログイン時の確認コード）をオンにする
  3. 急がせるメール・SMS・DM のリンクは開かず、公式の入り口から確かめる

エンジニア向け

ここから先は、サービスの開発や運用をしている人向けの情報です。前号で既出の話は続報だけ載せています。

1. Fireworks AI の侵害の波及：Cursor のマーケットプレイスに改ざん版の Claude Code 拡張（10/29）

  • Cursor の公表（The Hacker News 11/15）：Cursor が Fireworks AI に発行していたアクセスキーが Fireworks 側から漏れ、共有用の読み取り専用バケット（Privacy Mode でないセッションのエージェントの記録、主に 2025年）がコピーされた。一部は認証情報が伏せられておらず、顧客の 0.01% 未満の API 認証情報が露出。
  • 攻撃者は盗んだ認証情報で、10/29 に Cursor の拡張マーケットプレイスのキャッシュへ改ざん版の Claude Code 拡張を置いた。常駐する SSH の裏口を入れようとする。約11時間公開され、最大 5,000 人が受け取った可能性。対象は 2.1.312 / 2.1.313 をその時間に Cursor から入れた利用者で、Cursor が通知済み。
  • Cursor は、Privacy Mode の利用者・顧客のコードリポジトリ・本番環境・Cursor 本体と公式の更新・ほかの拡張への影響は確認されていないとしている。11/1 以降の不正な活動はなし。通信先などの痕跡は記事に無い。
  • やること：Cursor で 10/29 にこの拡張を入れた・更新した端末は、~/.cursor/extensions の版を確認し、拡張を入れ直し、~/.ssh/authorized_keys と常駐（launchd・cron・systemd）を確認、端末から使えた鍵・トークンを交換。Privacy Mode を使っていなかった時期にエージェントやサポートへ渡した認証情報も交換。
  • 同じ侵害で Notion AI（Insights の分類処理に使われた入力・応答の一部、10/5〜24、全ワークスペースの1%未満。Notion は 11/11 に対象メッセージ内の Notion API キーを失効）。ワークスペースの管理者は PC 版の「？」→「セキュリティインシデントのレビュー」で対象を確認し、会話に含まれた API キー・トークンを発行元で失効させる。

2. KARTE（プレイド）：不正アクセスで全プロジェクトの全機能を停止中（11/13〜）

  • 11/13 14:44 に緊急メンテナンスを告知。Web・アプリの計測、各種配信、管理画面を含む全機能が対象。KARTE Message の一括配信や Datahub のジョブは途中で止まることがある。
  • 11/13 23:35・11/15 16:01 に「外部に流出した可能性のある情報を確認し、該当顧客へメールで連絡」。11/15 時点で対象環境のネットワーク遮断は完了。流出した情報の種類・件数、原因、再開時期は未公表。
  • やること：KARTE を導入しているサービスは、外部サービス連携用の認証情報（シークレットキー、アクセストークン等）を無効化（プレイドが依頼）。計測・接客・配信が止まっている前提で自サービスの動作を確認し、status.karte.io を追う。

3. eMudhra 続報：G1 の期限は今日。Microsoft は今日から残りのルートを削除、Apple は cert.pem から 5 ルートを削除済み

  • Chrome：一番早い SCT が 2026-11-16 23:59:59 UTC より後の emSign Root CA - G1 の証明書を信頼しない（CCADB の公開リストでの告知）。Firefox も同じ日時の distrust-after（Mozilla bug 2089115）。それ以前の証明書は有効期限まで使える。
  • Microsoft：11/16 から、G1 を含む eMudhra の残り 10 ルートを削除。既存の証明書も Windows・Edge で既定では信頼されなくなる。Apple：11/30 に G1 の証明書すべての信頼を終える（eMudhra の案内による）。
  • Apple は 11/9 の macOS 27.2.1 / 26.7.3 / 15.8.3 で /etc/ssl/cert.pem から emSign ECC Root CA - G3・emSign Root CA - G1・emSign Root CA - C1・emSign ECC Root CA - C3・AAA Certificate Services を外し、標準の curl・git などが漏えいした中間 CA の 12 枚を受け付けなくなった（サポート記事 149555）。この束だけを見るツールは、これらにつながるチェーンのサイトで検証に失敗しうる。古い Sectigo 系のチェーン（AAA）を返しているサーバーは中間証明書を見直す。
  • eMudhra は 10/19 に「影響なし」としていた RSA の中間 CA 8 つ（TLS 6・コード署名 2、発行済み 195 枚）も 10 月下旬に失効（理由コードは cessationOfOperation）。
  • やること：自社のサイト・API の証明書チェーンに emSign / eMudhra / InCommon … G2C があれば、Windows から使われるホストを優先して別の CA で取り直す。CAA レコードを使っていれば新しい CA を先に足す。

4. PostgreSQL 18.7 / 17.12 / 16.16 / 15.20 / 14.25（11/12、52 件）

  • CVE-2026-6460（CVSS 8.8）：複合型の型の取り違え。オブジェクトを作れる DB ユーザーが、PostgreSQL を動かす OS アカウントの権限でコード実行。研究者が 18.6 で動く解説（最後の手順は省略）を公開。悪用の報告はない。
  • CVE-2026-116322：認証なしで PostgreSQL 18 のサーバーを再起動させられる。クライアント側では、細工したアーカイブで pg_restore が、侵害された接続元で psql がコード実行。
  • やること：サーバーとクライアントツールを更新、C 言語の拡張を作り直す、新設の composite_type_mismatch は無効にしない、リリース告知の再インデックス手順を行う。14 系は 14.25 が最後、13 以前は修正なし。マネージドサービスは各社の適用状況を確認。

5. CISA KEV に 11/13 追加：UnrealIRCd と Check Point

  • UnrealIRCd CVE-2026-114713（CVSS 8.6、6.0.0〜6.2.7.1 未満）：利用者がサーバー間コマンドを注入できる。修正版は 6.2.7.1。
  • Check Point CVE-2026-123039（Gaia OS の権限昇格）：PHP2Shell で侵入した攻撃者が root を取り、裏口や VMware ESXi のワイパーを置くのに使っている（10/30〜）。緊急の修正が出ている。

  • 集計サイトによると、ニトリ（11/9、最大3,762万件の可能性）、マネックス証券（11/13、委託先の口座開設システム。メール最大113万件・本人確認書類の画像 1,592件）、paiza（11/13、ステージング環境の認証の不備で最大約90万件のおそれ）なども公表されている（各社の発表原文は未確認）。ステージングや検証環境にも本番と同じ認証とデータの最小化を。
