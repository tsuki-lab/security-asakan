セキュリティ朝刊

11月23日（月）の朝刊

今日のひとこと：タワーレコードの通販を使ったことがあり、そのパスワードを他のサービスでも使っているなら、他のサービスのパスワードを今日変えてください。

1タワーレコードの通販サイトから約1,100万件が流出。パスワードの情報も

CD や本の通販「タワーレコード オンライン」に不正アクセスがあり、約1,100万件の会員情報が流出したと発表されました。

流出したのは、メールアドレスと、パスワードを暗号化した値（ハッシュ値）が約1,021万件、氏名・生年月日などが約278万件、住所・電話番号が約78万件です。退会して3年以内の人も含まれます。クレジットカードの情報は含まれていないとしています。パスワードは暗号化されていても、短いものや単純なものは割り出されるおそれがあります。

みんながやること
  • タワーレコード オンラインと同じパスワードを使っているサービスがあれば、そちらのパスワードを変える
  • パスワードはサービスごとに変える。覚えきれなければパスワード管理アプリを使う
  • 「流出のお詫び」「パスワードの再設定」を名乗るメールのリンクは開かず、公式サイトから確かめる

ハッシュ値：パスワードをそのまま保存せず、元に戻せない形に変えた値。ただし、よく使われるパスワードは総当たりで見つけられてしまうことがあります。

2ZOZOTOWN・WEAR の会員情報も流出。合わせて2,900万人近く

ファッション通販の ZOZO は、外部のサービスへの不正アクセスにより、ZOZOTOWN 約1,518万人、WEAR 約1,393万人の会員情報が漏れたと発表しました。

ZOZOTOWN では会員番号・年齢・性別・郵便番号が、うち約4.7万人はメールアドレスと電話番号も対象です。WEAR は会員番号・年齢・性別です。パスワードとカード情報は対象ではないとしています。退会した人も含まれます。この外部のサービス（KARTE）を通じた流出は、銀行や通販など多くの会社に広がっています。

みんながやること
  • ZOZO からのお知らせは、メールのリンクからではなく、公式アプリや公式サイトで確かめる
  • 「注文の確認」「返金」「本人確認」を口実にしたメール・SMS・電話で、パスワードやカード番号を入力・回答しない
  • 偽のサイトにパスワードを入れてしまったら、すぐ本物のサイトで変更する

3AI に送った文章が、裏側の会社で盗み見られていた

いろいろな AI をまとめて使えるサービスの裏側で、AI を動かしている3つの会社の内部から、利用者が送った文章（プロンプト）が数か月にわたって盗まれていたことが、研究者の調査で分かりました。

「データを残さない」設定で送った文章も含まれていました。研究者がわざと混ぜておいた偽のパスワードは、実際に使われようとしました。AI に送った文章は、表に見えている会社だけでなく、その先の複数の会社を通ることがあります。

みんながやること
  • AI にパスワード・暗証番号・カード番号・人に見られたくない個人情報を貼らない
  • 貼ったことがあるなら、そのパスワードを変える
  • AI のサービスは、運営元がはっきりしたものを選ぶ

プロンプト：AI に送る質問や指示の文章。貼り付けた資料やメールの文面も含まれます。

いつでも効く3つの基本

  1. OS・アプリ・ブラウザは自動更新をオンにして、ときどき再起動する
  2. パスワードはサービスごとに変え、二段階認証（ログイン時の確認コード）やパスキーをオンにする
  3. 急がせるメール・SMS・DM のリンクは開かず、公式の入り口から確かめる

エンジニア向け

ここから先は、サービスの開発や運用をしている人向けの情報です。前号で既出の話は続報だけ載せています。

1. Ruby「Ruby2Shell」CVE-2026-132825：実証コードの公開予定（11/25 以降）まであと2日

  • 修正版は 4.0.10 / 3.4.13 / 3.3.14（11/18）。標準の Rails（api_only 以外）とクラシック形式の Sinatra は Rack::MethodOverride 経由で認証の前に届くとされる。3.2 以前は修正なし。
  • gem の更新では直らない。動いているプロセスの Ruby の版を確かめ、上げてアプリサーバーを再起動する。攻撃の報告は今朝の時点でも見つかっていない。

2. npm：simple-git（CVE-2026-134815）・binary-parser（CVE-2026-134814）、どちらも CVSS 9.2

  • simple-git 4.1.0 未満・@simple-git/argv-parser 3.0.0 未満：listRemote() / raw() に渡す引数に外から手を入れられると、ls-remote・archive・fetch-pack・send-pack に --exec を差し込み、allowUnsafePack の確認を越えてコマンドを実行される。修正版は npm に 11/16 に出ている（レジストリで確認）。
  • binary-parser 2.3.1 未満：パーサー定義の文字列オプションが検査されず、定義を外から決められるとコンパイル時に Node のプロセスでコードが動く。2.3.1（11/11）で修正。
  • 悪用・公開の実証コードの報告はない。間接依存にも入りやすいので、ロックファイルで版を確かめる。
  • 同じ日の新着に Gunicorn の ASGI パーサー（CVE-2026-134821・CVE-2026-134820）、Gradio の Host ヘッダー偽装による認証回避（CVE-2026-134825）、Portainer の認可回避（CVE-2026-134804）、Weblate のパスワード再設定でのアカウント乗っ取り（CVE-2026-134838）。修正版は各 advisory で確かめてください。

3. Ghostscript CVE-2026-125396：細工したファイルで -dSAFER を抜けてコマンド実行

  • フォント読み込みの use-after-free。研究者は Roundcube の添付、WordPress のアップロードフォーム（Forminator・Essential Addons for Elementor）、共有の印刷キューなど約10の経路で実証した。攻撃の報告はない。
  • 修正：Ghostscript 10.08.0（9/8）。Debian 12 は未修正、Amazon Linux・SUSE は対応中。コンテナやアプリに同梱した Ghostscript は OS の更新では置き換わらない。
  • ImageMagick・Pillow・libvips などは拡張子と関係なく PostScript / EPS を Ghostscript に渡すことがある。受け付ける形式を絞る（ImageMagick の policy.xml で PS / EPS / PDF を無効化など）、AppArmor で gs からシェルを起動させない。WordPress は 7.0.4 以上（アップロード経路は別の CVE-2026-65640）。

4. Apache HTTP Server 2.4.71（11/11、前号までに未掲載）：mod_http2 CVE-2026-119618

  • 対象は 2.4.55〜2.4.70 で HTTP/2 を有効にしたもの。競合状態で、認証なしのコード実行のおそれ（Red Hat は CVSS 9.8）。独立した mod_h2 の 2.0.8〜2.0.42 も対象で、こちらはアーカイブ済みのため修正なし。
  • RHEL 9 / 10 は修正済み（RHEL 6〜8 は対象外）。Debian の安定版は修正待ち。公式の回避策はなく、Protocols から h2 / h2c を外して http/1.1 だけにする方法が勧められている（各バーチャルホストも）。
  • 悪用の状況は、Red Hat が「確実な攻撃手法が示された」、Wiz が「実証コードも悪用もない」と分かれている。

5. AI 推論の中継：推論事業者の内部からプロンプトが数か月盗まれていた

  • Dragos が 7〜11月に約200万件のプロンプトに偽の認証情報を仕込み、3つの推論事業者の内部で読まれていたことを見つけた。Zero Data Retention の要求も含む。仕込んだ AWS の鍵は S3・Secrets Manager・Parameter Store の探索や IAM ユーザー作成の試みに使われた。
  • OpenRouter は自社の侵害はないとし、3事業者を外し、125 のエンドポイントを ZDR の対象から外した（社名は非公表）。Phala は 10/21〜11/8 の DeepSeek の1モデルへの要求を漏えい扱いに。Together AI は AI コーディングエージェントが公開リポジトリに認証情報をコミットしたことで、6〜7月の保存サンプルを取られた。
  • やること：プロンプト・エージェントのコンテキストに入った鍵を交換する、上流の事業者を自分で選ぶ、カナリアトークンを仕込んで使われたら事故として扱う。

6. 情報漏洩（開発・運用の目線で）

  • タワーレコード オンライン：メールアドレス・会員ID・パスワードのハッシュ値 10,214,652件。侵入の方法は非公表。同じ認証情報でのリスト型攻撃が来ることを前提に、自社サービスのログイン試行の監視とレート制限を見直す。
  • ZOZO：KARTE への 11/13 の不正アクセスで、ZOZOTOWN 約1,518万人・WEAR 約1,393万人・出店ブランド担当者 約2.4万人。外部の SaaS に連携しているデータの範囲と、連携用の認証情報を棚卸しする。
