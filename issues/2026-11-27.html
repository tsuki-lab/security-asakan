セキュリティ朝刊

11月27日（金）の朝刊

今日のひとこと：メールや SMS のリンクからアプリを入れないでください。アプリは必ず公式のアプリストアから。

1パスワード管理の 1Password に不正アクセス。保存したパスワードは無事

パスワード管理サービスの 1Password は、社員のアカウントが乗っ取られ、一部の利用者の名前やメールアドレスなどが盗まれたと発表しました。

盗まれたのは名前・メールアドレス・アカウントの登録日などと、招待や復旧のメールに入っているリンクの一部です。保存しているパスワードやその中身、ログイン用のパスワードと秘密の鍵は盗まれていないとしています。影響のあった人には個別にメールで知らせています。

みんながやること
  • 1Password を使っていても、会社はパスワードの変更などは必要ないとしている。慌てて設定を変えなくてよい
  • 1Password を名乗る「招待」「アカウントの復旧」のメールのリンクは開かず、アプリから確かめる

2東京都「赤ちゃんファースト」の QUOカードPay が使えなくなる

東京都の子育て支援「赤ちゃんファースト」で交換した QUOカードPay が、使えない・残高が0になる事態が起き、都は委託先の会社への不正アクセスが原因としています。

報道では約1万2千人分・計約9千万円分が使えなくなりました。都と委託先のリンベルは、使えなくなった残りの金額分を作り直して、登録したメールアドレスに送るとしています（1週間ほどかかる見込み）。リンベルは自社の通販サイトの会員など約250万人分の個人情報が漏れたおそれも公表しています。

みんながやること
  • 交換した QUOカードPay の残高を確かめ、リンベルからの再発行のメールを待つ
  • リンベルや東京都を名乗る「再発行の手続き」などのメール・電話で、カード番号や暗証番号を入れない。迷ったら都の公式サイトから確かめる

3保険会社を装って、スマホに不正なアプリを入れさせるメールが急増

第一生命などをかたり、「保険の手続き」「控除証明書」などを口実に、Android のスマホに不正なアプリ（悪いことをするアプリ）を入れさせるメールが急に増えています。

偽のサイトは保険の契約内容を確認できるように見せかけますが、実際には関係のないアプリを入れさせます。また、ENEOS は公式アプリに外部からの不正なアクセスがあったとしてアプリを止めていて（給油はふだんどおり）、ENEOS を名乗る連絡にも注意を呼びかけています。

みんながやること
  • メールや SMS のリンクからアプリを入れない。アプリは Google Play などの公式ストアから
  • 保険の手続きは、保険証券や公式サイトに書かれた窓口から確かめる

控除証明書：年末調整や確定申告で、払った保険料を申告するときに使う書類。この時期に届くので、口実に使われやすい。

いつでも効く3つの基本

  1. OS・アプリ・ブラウザは自動更新をオンにして、ときどき再起動する
  2. パスワードはサービスごとに変え、二段階認証（ログイン時の確認コード）やパスキーをオンにする
  3. 急がせるメール・SMS・DM・電話には従わず、公式の入り口から確かめる

エンジニア向け

ここから先は、サービスの開発や運用をしている人向けの情報です。前号で既出の話は続報だけ載せています。

1. Drupal SA-CORE-2026-019「Access bypass」CVE-2026-136716（Highly critical）：悪用あり

  • 11/18 の Fail2Install（CVE-2026-132165）の修正の後も、インストールが中途半端・普通でない状態のサイトは乗っ取れた（CWE-754）。本番サイトも含み、その状態は管理画面からは見えない。Drupal は実際の悪用を確認している（11/25）。
  • 修正版：11.4.14 / 11.3.23 / 10.6.23（前号の 11.4.13 / 11.3.22 / 10.6.22 では足りない）。11.0〜11.2・10.5 以前は修正なし。更新後に update.php。インストーラ（install.php）を外から届かないようにしていたサイトは対象外。
  • 確認：ログで不正アクセス、特に user 1 の変更を探す。user 1 のメールアドレスが自分の管理下にあるか確かめ、パスワード再設定を検討。すでに乗っ取られたサイトは脆弱に見えないことがある。

2. PolinRider（北朝鮮系とされる）：盗んだ GitHub トークンで 7,609 リポジトリのコミットを書き換え

  • 作者・メッセージ・日付を保ったまま最近のコミットを書き換え、ビルド設定の数百の空白の後ろや conftest.py・小さな utils にローダーを隠し、30〜40分後に force-push で消す。最新の波は VS Code でフォルダを開くだけで動く（.vscode/tasks.json）。設定は Ethereum の取引から読み、切り離した node -i で次の段階を動かして、環境変数の秘密・ブラウザのパスワードと Cookie・ウォレットを盗む。
  • npm：itsa-utils@1.4.2・itsa-jsext@2.0.3・itsa-cli@16.5.3・itsa-react-*（乗っ取った保守者アカウントから）、版は不明だが @adminide-stack/*・server-hemera-mongo・cdeops・@cdmbase/wiki-browser・@pubngo-stack/help-browser。VS Code 拡張 huntrole.assessment-tool（偽の採用課題）。
  • 痕跡：文字列 68656c6C6f6970626f742121、C2 103.179.142.155・95.135.181.84・95.135.181.151（443）、パス /0x/cls・/0x/ls。
  • やること：リポジトリの force-push・覚えのないコミットを確かめ、手元のコピーと比べる。知らない相手の「採用課題」はビルド・テスト・VS Code で開く前に中身を読む。該当すれば GitHub・npm のトークンと SSH 鍵を交換。

3. 1Password：従業員の GitHub アカウント経由でバックエンドに不正なコード

  • 11/19 に調査を開始、11/25 に公表。非公開リポジトリのコードの複製と CI/CD への侵入もあった。一部の顧客の氏名・メール・ID・公開鍵・SRP のパラメータ・招待や復旧のリンクのトークンが流出。保管庫・アカウントのパスワード・Secret Key・復旧キー・配布済みのアプリと拡張は影響なし。
  • トークン単独では入れない（SSO かメールの確認コードが要る）。1Password は確認コードを6桁の数字から10文字に延ばした。従業員の GitHub アカウントとトークンが入り口になる例として、自分の組織の GitHub のトークンの権限と期限も見直したい。
