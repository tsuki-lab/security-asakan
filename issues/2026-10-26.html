セキュリティ朝刊

10月26日（月）の朝刊

今日のひとこと：週明けにブラウザとスマホを「最新に更新して再起動」。あす Chrome が一段階対策を進めます。

1あす Chrome が、流出した鍵の会社の古い「身元保証」を外します

Chrome は日本時間の28日未明に、インドの会社 eMudhra の古い登録を外す予定です。

先日お伝えした eMudhra の鍵の流出について、新しい被害の報告はありません。Chrome は予定どおり、米国時間10月27日（日本時間では28日未明）に、この会社の古い「身元保証」の登録そのものを外す見込みです。その日から、この会社の証明書を使ったままのサイトでは、警告の画面が出ることがあります。この会社は Web サイト向けの証明書の事業から撤退する方針で、今のところ鍵が悪用されたという報告はありません。

みんながやること
  • Chrome を最新にして、一度閉じて開き直す
  • 警告画面が出たサイトは、先へ進まずに閉じる。普段使うサイトなら、運営からのお知らせを待つ

2会社や学校のネットワーク機器への攻撃は続いています

個人のスマホやパソコンへの直接の影響はありませんが、勤め先の機器が狙われています。

拠点どうしをつなぐ機器（Arista の VeloCloud）の欠陥が実際に悪用されていると、米国政府機関（CISA）が警告しています。新しい種類の被害は今朝の時点で見当たりませんが、更新がまだの機器は狙われ続けます。

みんながやること
  • 勤め先で機器を担当している人は、メーカーの案内に沿って更新する
  • それ以外の人は、会社からの「更新してください」という連絡に従って、早めに再起動や更新を済ませる

いつでも効く3つの基本

  1. OS・アプリ・ブラウザは自動更新をオンにして、ときどき再起動する
  2. パスワードはサービスごとに変え、二段階認証（ログイン時の確認コード）をオンにする
  3. 急がせるメール・SMS・DM のリンクは開かず、公式の入り口から確かめる

エンジニア向け

ここから先は、サービスの開発や運用をしている人向けの情報です。前号で既出の話は続報だけ載せています。

1. eMudhra：Chrome の G3 削除は 10/27（PT）の予定

  • Chrome は emSign ECC Root CA – G3 を 10/27 朝（米国太平洋時間）＝日本時間 28日未明に Chrome Root Store から外す見込み。G3 の下の証明書を使うサイトは全画面の警告が出うる。Chrome は 10/17 の CRLSet 更新で、問題の中間証明書をすでに遮断している。
  • Mozilla は 10/20 の NSS 3.131.1 で G3 を削除済み。Ubuntu も 10/20 の更新で emSign ECC Root CA - G3 を ca-certificates から外した（USN-8944-1）。
  • Google は eMudhra の残りのルート（emSign Root CA – G1）も見直し中と報じられている。Mozilla は今のところ残している。
  • ブラウザ以外（コンテナ・CI・独自の信頼リストを持つアプリ）は、更新するまで古いルートを信頼し続けうる。自分のサイトの証明書の発行元に emSign / eMudhra が無いか確認し、あれば別の認証局で取り直す。
  • Apple の対応と修正版（Node 22.23.4 / 24.22.1 / 26.12.1、certifi 2026.10.18、Go 1.27.3 / 1.26.10 など）は前号のまま。macOS の /etc/ssl/cert.pem の更新は、今朝の時点で確認できていない。

2. PHP：回避策と修正版は前号のまま

  • PHP2Shell（CVE-2026-109618 / 109619）の修正版は 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35。mod_php が最も危険とされる。PHP 8.1 以前は公式の修正なし（配布元の移植を確認）。
  • CVE-2026-115560 は修正版待ち。回避策 session.upload_progress.enabled=0。

3. Arista VeloCloud Orchestrator：CVE-2026-114625（悪用あり）

  • オンプレミス版の SQL インジェクション（CVSS 9.9）。Arista が 10/22 に公表し、悪用を確認したとしている。CISA が 10/23 に悪用済みリストへ追加。
  • 使っていれば Arista の案内の修正版へ。外部から管理画面に届く状態なら、更新まで遮断する。

4. LiteLLM 1.107.0：新しい動きなし

  • 安全な版は 1.106.2。入れた環境は作り直し、そこから届く鍵とトークンをすべて交換する。/tmp/.pc_once_* があれば情報の送信はすでに起きている。10/21 に PyPI と Docker の latest 系を取ったものも対象。
