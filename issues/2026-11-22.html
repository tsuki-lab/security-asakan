セキュリティ朝刊

11月22日（日）の朝刊

今日のひとこと：「流出のお詫び」や「口座の確認」を名乗る連絡が来たら、リンクは開かず、公式アプリか勤め先の担当に確かめてください。

1持株会のシステムから最大5万6千人分の情報が流出。振り込み先の口座の情報も

SMBC日興証券は、会社の「持株会」の事務に使っているシステムに不正アクセスがあり、最大56,487人分の情報が漏れたと発表しました。

対象は、氏名・住所・持っている株の残高・配当金、そして振り込み先の口座の情報などです。同社は、対象の持株会に個別に連絡するとしています。パスワードが漏れたという発表はありません。また、11月に大量の流出が分かったメール配信サービス「Cuenote」は、件数を数え直し、延べ約4,786万件（メールアドレス・氏名など）に修正しました。

みんながやること
  • 勤め先の持株会に入っている人は、会社や証券会社からのお知らせを確かめる
  • 「振り込み先の口座を確認・変更してください」という連絡は、メールや SMS のリンクからではなく、勤め先の担当や公式の窓口に確かめる
  • 残高や配当の額を知った上での電話・メールでも、詐欺を疑う

持株会：勤め先の会社の株を、給料から少しずつ積み立てて買う制度。事務は証券会社が引き受けていることが多く、会員の情報もそこで預かっています。

2AI アシスタントに任せすぎない。悪いページ1つで会話の中身を抜かれた研究も

代わりにネットを見て買い物までこなす「AI エージェント」で、悪意のあるページを1つ開かせるだけで、利用者の会話履歴や覚えさせた情報を抜き出せたという研究が発表されました。

対象は Meta の AI エージェント「Muse」で、研究者は公開する前に欠陥は直されたと説明しています（実験の環境での話で、実際の被害は報告されていません）。一方、メッセージアプリの Signal は、スマホの AI が画面を読み取って会話の中身を取り込むのを防ぐため、Android と iPhone で画面の読み取りを止める設定を最初からオンにしました。

みんながやること
  • AI アシスタントにつないでいるアカウント（メール・買い物・カレンダーなど）を見直し、使っていないものは外す
  • AI に、知らないサイトやメールのリンクを開かせない。支払いを任せる設定は慎重に
  • Signal を使っている人は、その保護の設定をオンのままにしておく

AI エージェント：質問に答えるだけでなく、ネットを見たり、予約や買い物をしたりと、利用者の代わりに作業まで行う AI。つないだアカウントの権限をそのまま使います。

3サポートが終わったネット機器は、欠陥が見つかっても直らない

ネットワーク機器メーカーの SonicWall は、古い世代の「ファイアウォール」（会社のネットの出入り口を守る機器）には、重大な欠陥でも修正を出さないとして、すぐに置き換えるよう呼びかけました。

AI を使って、サポートが切れた機器を素早く見つけて攻撃する動きが強まっていると説明しています。家庭用の Wi-Fi ルーターでも、メーカーのサポートが終わると更新が出なくなります。

みんながやること
  • 家の Wi-Fi ルーターの型番で、メーカーのサイトに「サポート終了」と出ていないか確かめる。終わっていれば買い替えを考える
  • ルーターの自動更新をオンにし、管理画面のパスワードを初期のままにしない
  • お店や事務所で使っている機器は、保守をしている業者にサポートの期限を聞いておく

いつでも効く3つの基本

  1. OS・アプリ・ブラウザは自動更新をオンにして、ときどき再起動する
  2. パスワードはサービスごとに変え、二段階認証（ログイン時の確認コード）やパスキーをオンにする
  3. 急がせるメール・SMS・DM のリンクは開かず、公式の入り口から確かめる

エンジニア向け

ここから先は、サービスの開発や運用をしている人向けの情報です。前号で既出の話は続報だけ載せています。

1. Ruby「Ruby2Shell」CVE-2026-132825：実証コードの公開予定（11/25 以降）まであと3日

  • 修正版は 4.0.10 / 3.4.13 / 3.3.14（11/18）。標準の Rails（api_only 以外）とクラシック形式の Sinatra は Rack::MethodOverride 経由で認証の前に届くとされる。3.2 以前は修正なし。
  • gem の更新では直らない。動いているプロセスの Ruby の版を確かめ、上げてアプリサーバーを再起動する。攻撃の報告は今朝の時点でも見つかっておらず、CISA KEV にも入っていない。詳細は前号を参照。

2. GnuPG の GPGME に二重解放 CVE-2026-129975

  • ユーザー ID が極端に長い OpenPGP の鍵を読むと、read_status() / read_colon_line() で二重解放が起きる。GnuPG はコード実行も否定できないとしている。攻撃の報告はない。
  • 対象：GPGME の 2.3.0 より前のすべて（共有ライブラリ・Windows の DLL・静的リンク）。多くのメールクライアント・XMPP クライアント・Samba・Gpg4win などが使う。GPGMEPP・GPGMEQT は更新不要。
  • 修正：GPGME 2.3.1（2.3.0 は公開されていない）、旧系列 1.24.4、Windows は Gpg4win 5.1.2。回避策はない。コンテナに入れている libgpgme、言語バインディング（Python の gpg、Ruby の gpgme gem など）が抱える版も確かめる。
  • 公表は 11/25 の予定だったが、Ruby2Shell の公表を受けて前倒しされた。

3. Fastify：@fastify/express・@fastify/middie の認証回避（CVSS 9.1）

  • @fastify/express 4.0.10 未満：パスを限って付けたミドルウェア（認証など）を、パーセントエンコードの解釈の違い・パスの前方一致のずれ・空のルートパラメータ・正規表現でのマウント・大文字小文字の違いで素通りできる（CVE-2026-133120・CVE-2026-129504・CVE-2026-124626・CVE-2026-133867、CVE-2026-129850 は 7.4。GHSA-w877-hjcp-88rc）。
  • @fastify/middie 9.3.7 以前：パスを限ったミドルウェアの認証回避（CVE-2026-133250。GHSA-gcf6-j9m3-p97x）。
  • npm には @fastify/express 4.0.10 / 4.0.11、@fastify/middie 9.3.8 / 9.3.9 が出ている（レジストリで確認）。
  • すぐ上げられなければ：認証は Fastify の preHandler フックで request.routeOptions.url を見て行い、* で始まる・バックスラッシュを含む要求は onRequest で拒否する。

4. cve.now の新着から（修正版は各 advisory で確かめてください）

  • Better Auth：OAuth サインインで未確認のメールによるアカウント乗っ取り（CVE-2026-134312）、メール変更のリンク（CVE-2026-134315）、電話番号プラグイン（CVE-2026-134322、8.6）、admin の update-user での権限昇格（CVE-2026-134311）など十数件。@better-auth/electron は 1.7.16 で修正とされる。
  • SurrealDB：埋め込み JavaScript の権限の回避（CVE-2026-134292、9.3）ほか多数。Admidio：ロール名からのコード注入（CVE-2026-134262、9.2）。
  • WordPress のプラグイン Nexter Blocks Pro：認証なしの権限昇格（CVE-2026-125294、9.8）。D-Link DIR-600L：認証なしのスタックあふれ（CVE-2026-133993、10.0）。

5. SonicWall 第6世代（SonicOS 6.x）は修正が出ない

  • TZ300〜600、SOHO / SOHO 250、NSA 2600〜6600、NSa 2650〜9650、NSsp 12400 / 12800、SuperMassive 9200〜9800、NSv（第6世代）。SonicOS 8 の第8世代への置き換えを求めている。
  • 置き換えまで：WAN 側の管理（HTTPS・SSH・SNMP）を閉じる、SSL VPN を止めるか接続元を絞る、管理者とリモートアクセスに多要素認証、ローカルのパスワードを変える、ログで不審なログイン・設定変更を見る。

6. 情報漏洩（原因が分かっているもの）

  • ユミルリンク（Cuenote）第三報：サポート担当者の認証情報を、プログラムの欠陥を突いて取られた。経路は2つ。不正なプログラムでデータベースから直接出し、内部ネットワークで別のサーバーへ移る方法と、ログイン中の正規の利用者のセッションを盗んで管理画面の CSV 出力で持ち出す方法。件数は重複を除いて延べ 47,864,147件（Cuenote FC の49システム）に修正。
  • SMBC日興証券：持株会の事務のシステムに 11/9 に不正アクセス、最大56,487名。原因は調査中。
